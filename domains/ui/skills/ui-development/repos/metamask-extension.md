# MetaMask Extension overlay

Platform rules for React web UI in `metamask-extension`. The base above covers
sources, component choice, foundations, typography, migration, and the shared
accessibility rules.

Strategy: [Agentic Design System Strategy](../../../knowledge/agentic-design-system-strategy.md)

## Packages and paths

- Components and enums: `@metamask/design-system-react`. Do not import enums
  from `@metamask/design-system-shared`; that package is listed in the Tailwind
  `content` globs only so its classes are generated.
- Inventory and deprecations: the
  [React components manifest](https://metamask.github.io/metamask-design-system/manifests/components.json),
  confirmed against `node_modules/@metamask/design-system-react/dist/components/index.d.cts`.
- README: `packages/design-system-react/src/components/<Component>/README.mdx`
  at the tag `@metamask/design-system-react@<installed version>`.
- Legacy component library: `ui/components/component-library` (being
  deprecated in favor of MMDS). Do not add new usage where MMDS covers the need.
- Existing feature UI that is intentionally outside MMDS lives under
  `ui/components/` (for example `ui/components/ui/marketing-moment`). Reuse it
  before building new feature UI.

Do not apply React Native guidance or APIs (`twClassName`, twrnc,
`accessibilityRole`, `BottomSheet`) to Extension.

## Styling surface

- `tailwind.config.js` uses `@metamask/design-system-tailwind-preset`
  (Tailwind CSS v3) and removes the default palette and font sizes. Use only
  classes that configuration generates. If a class is in doubt, check the
  preset source or the built CSS; do not invent one or add a safelist entry.
- Use Tailwind class names (`className`) for styling and layout. Do not create
  or modify SASS or SCSS files.
- Set type with `Text` variants. Font-size utilities do not exist in this
  config, so `text-[14px]` and similar are always wrong.

## Extension accessibility mechanics

- Icon-only controls need an accessible name: `ButtonIcon` takes `ariaLabel`.
  Search fields need an input label; check the installed `TextFieldSearch`
  types for the prop name.
- Announce async errors and status with `role="alert"` or
  `aria-live="polite"` on a container that is already mounted before its text
  changes.
- Expandable controls expose `aria-expanded`; toggles and tabs expose their
  selected or pressed state.
- Preserve the keyboard behavior documented in the component README and
  stories, including focus order and how popovers and modals close.

## Incremental migration paths

The legacy barrel is `ui/components/component-library` (`Box`, `Text`,
`Button`, `Icon`, and the rest). Apply the base `Legacy*` rule to any export
from that barrel whose name MMDS also exports, including enums such as
`IconName`. Adjust the `../` depth to the file.

```tsx
// Do: MMDS keeps the plain names. Legacy gets the prefix.
import { Box, Text } from '@metamask/design-system-react';
import { Box as LegacyBox, Text as LegacyText } from '../../component-library';

// Don't: prefix the MMDS import, or leave both on the plain name.
import { Box as LegacyBox, Text as LegacyText } from '@metamask/design-system-react';
import { Box, Text } from '../../component-library';
```

Prop mapping from legacy to MMDS components:
[React `MIGRATION.md`](https://github.com/MetaMask/metamask-design-system/blob/main/packages/design-system-react/MIGRATION.md).

## Exceptions

When custom UI is necessary, use the repository's existing exception
documentation. Do not invent a new annotation format.

## Extension checklist

- [ ] Only classes generated by the Extension Tailwind config; no default
      palette, arbitrary values, or safelist workarounds.
- [ ] No SASS or SCSS files created or modified.
- [ ] No new usage of `ui/components/component-library` where MMDS covers the
      need; clashing legacy imports are aliased `Legacy*`.
- [ ] Icon-only controls and search fields have accessible names; status
      changes are announced; keyboard behavior still works.
