# MMDS Figma Code Connect

Code Connect shows real MMDS snippets in Figma Dev Mode, with a React and a
React Native option. Product teams and agents read those snippets, so they
must use the same API consumers import.

Lookup order: `knowledge/mmds-sources.md` (source:
[`../../knowledge/mmds-sources.md`](../../knowledge/mmds-sources.md)). For a
pattern, mirror an existing `.figma.tsx` in the same package that follows
these rules. Const naming: `component-architecture`.

## When to use

- A component gains or changes a Figma counterpart, or its props change.
- Dev Mode shows a wrong import, a string literal, or a placeholder value.

## Workflow

1. Generate the file with the interactive wizard for each platform (overlay).
2. Fix the generated file against the rules below.
3. Dry-run, then publish (CI publishes on merge to `main`).
4. Check Dev Mode: platform dropdown, platform package imports, realistic
   examples.

## File rules

- Colocate `<ComponentName>.figma.tsx` with the component, on both platforms.
- First line disables the default-import lint rule for `figma`; then the
  auto-generated header comment naming the platform implementation.
- Import the component and its const objects from the component barrel
  (`'.'`), using component-scoped names, never base scales from
  `@metamask/design-system-shared`.

```tsx
// eslint-disable-next-line import-x/no-named-as-default
import figma from '@figma/code-connect';
import React from 'react';

import { ComponentName } from './ComponentName';
import { ComponentNameVariant, ComponentNameSize } from '.';

/**
 * -- This file was auto-generated by Code Connect --
 * React implementation of ComponentName
 */
figma.connect(ComponentName, '<Figma component URL with node-id>', {
  props: {
    variant: figma.enum('variant', {
      '<Figma option>': ComponentNameVariant.ValueA,
    }),
    isDisabled: figma.boolean('isDisabled'),
    label: figma.string('label'),
  },
  example: ({ label, ...props }) => (
    <ComponentName {...props}>{label}</ComponentName>
  ),
});
```

## Mappings

- `figma.enum`: Figma option names on the left, imported const members on
  the right. Never string literals. Read the members from the installed or
  source types; do not guess them.
- `figma.boolean` for booleans; `figma.boolean(name, { true: value, false:
  undefined })` for a value that depends on a Figma toggle.
- `figma.string` for text.
- `figma.nestedProps('<Figma layer>', { ... })` for props on a nested Figma
  component; nest a `figma.boolean` inside for a conditional string.
- Stateful examples may use React hooks (`useState`) when the component is
  controlled.

## Examples

- Realistic, meaningful values; every required prop present. Never
  "example", "test", "foo", or a truncated address such as `0x123`.
- Similar examples on both platforms.

## Build and test

`.figma.tsx` files are excluded from the TypeScript build and from Jest
coverage. Adding one needs no config change.

## Checklist

- [ ] Colocated on both platforms, header lines present.
- [ ] Component-scoped consts from `'.'`; no string literals; no base scales.
- [ ] Realistic example with all required props.
- [ ] Dry-run passes (it also runs in CI).
- [ ] Dev Mode shows both platforms with the right imports.
